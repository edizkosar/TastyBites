# 07.2 — Cancel Reservation Endpoint (`user/cancel_reservation.php`)

## 📋 File Info
- **Path:** `user/cancel_reservation.php`
- **Type:** POST-only endpoint (no HTML rendering)
- **Depends on:** `includes/db.php`, `includes/helpers.php`, `includes/auth_helpers.php`
- **Used by:** Cancel buttons in `user/dashboard.php`

## 🎯 Purpose
Transition a single reservation (owned by the current user, future, and in `pending`/`confirmed` state) to status `cancelled`. Always end with a redirect back to the dashboard with a flash.

## 📦 Required Behavior

1. `requireLogin();`
2. Require POST method. If not POST → flash danger + redirect dashboard.
3. Read and cast `reservation_id`. If missing/zero → flash danger + redirect.
4. Fetch the reservation by id WITH ownership check (`user_id = ?`). If not found → "Reservation not found." + redirect.
5. Validate state:
   - `status` MUST be `pending` or `confirmed`. Otherwise → "Only pending or confirmed reservations can be cancelled."
   - Date MUST be today or later. Otherwise → "Past reservations cannot be cancelled."
6. UPDATE `status = 'cancelled' WHERE id = ? AND user_id = ?`.
7. Success flash: "Reservation cancelled." (info)
8. Redirect to `/user/dashboard.php`.

## 🔧 Interface
None. Side-effecting endpoint.

## 🚫 Must NOT Do
- Don't render HTML — this file should never produce visible output.
- Don't allow GET. Reject early.
- Don't DELETE the row — only update status.
- Don't trust client-provided `user_id` (read from session via `currentUserId()`).
- Don't include header/footer.

## 📐 Code Skeleton

```php
<?php
require_once __DIR__ . '/../includes/db.php';
require_once __DIR__ . '/../includes/helpers.php';
require_once __DIR__ . '/../includes/auth_helpers.php';

requireLogin();

if (currentMethod() !== 'POST') {
    setFlash('Invalid request method.', 'danger');
    redirect('/user/dashboard.php');
}

$reservationId = (int)($_POST['reservation_id'] ?? 0);
if ($reservationId <= 0) {
    setFlash('Invalid reservation reference.', 'danger');
    redirect('/user/dashboard.php');
}

$userId = currentUserId();

// Ownership + status fetch
$stmt = $db->prepare(
    "SELECT id, status, reservation_date
     FROM reservations
     WHERE id = ? AND user_id = ?
     LIMIT 1"
);
$stmt->bind_param('ii', $reservationId, $userId);
$stmt->execute();
$res = $stmt->get_result();
$row = $res->fetch_assoc();
$stmt->close();

if (!$row) {
    setFlash('Reservation not found.', 'danger');
    redirect('/user/dashboard.php');
}

if (!in_array($row['status'], ['pending', 'confirmed'], true)) {
    setFlash('Only pending or confirmed reservations can be cancelled.', 'warning');
    redirect('/user/dashboard.php');
}

if ($row['reservation_date'] < date('Y-m-d')) {
    setFlash('Past reservations cannot be cancelled.', 'warning');
    redirect('/user/dashboard.php');
}

// Update
$stmt = $db->prepare(
    "UPDATE reservations
     SET status = 'cancelled'
     WHERE id = ? AND user_id = ?"
);
$stmt->bind_param('ii', $reservationId, $userId);
$stmt->execute();
$stmt->close();

setFlash('Reservation cancelled.', 'info');
redirect('/user/dashboard.php');
```

## 🧹 Clean Code Reminders
- Each guard is a single `if` with an early redirect. No nesting.
- Two prepared statements: one to verify ownership/state, one to update.
- The UPDATE re-asserts `user_id = ?` as a defense-in-depth check (even though we already confirmed ownership).

### Functional tests
1. Logged out → GET or POST `/user/cancel_reservation.php` → redirect to login (via `requireLogin`).
2. Logged in, hit URL via GET (browser address bar) → redirected to dashboard with "Invalid request method."
3. Logged in, submit POST without `reservation_id` (use curl or DevTools) → "Invalid reservation reference."
4. Logged in as John, submit `reservation_id = 1` (John's confirmed future one) → row status becomes `cancelled`, dashboard shows "Reservation cancelled." flash, the row's status badge is now grey.
5. Submit again with the same id → "Only pending or confirmed reservations can be cancelled."
6. Submit with `reservation_id = 2` (John's past completed one) → "Only pending or confirmed reservations can be cancelled." (because status check fails before the date check).
7. Insert a row owned by another user, try cancelling its id as John → "Reservation not found." Row in DB untouched.
8. Edit a future pending reservation to be in the past via phpMyAdmin, then try to cancel → "Past reservations cannot be cancelled." (Verifies the date guard.)
