## 🚫 What Doesn't Belong

If the AI is tempted to create any of these, the answer is no:

- `vendor/`, `composer.json`, `composer.lock` — no Composer
- `node_modules/`, `package.json` — no npm
- `.env` — credentials live in `includes/config.php`
- `Gruntfile.js`, `gulpfile.js`, `webpack.config.js` — no build tools
- Any extra subfolder under `includes/` (e.g. `includes/classes/`) — flat layout only
- Per-page CSS files — single `assets/css/style.css`
- Helper files outside `includes/` — keep helpers centralized

## 📂 Path Conventions In Code

When PHP files reference each other, always use `__DIR__`:

```php
require_once __DIR__ . '/../includes/db.php';   // GOOD — relative to current file
require_once 'includes/db.php';                  // BAD  — relative to CWD, fragile
require_once '/var/www/.../db.php';              // BAD  — only works on one machine
```

When HTML references assets, always use the `BASE_URL` constant:

```php
<link rel="stylesheet" href="<?= BASE_URL ?>/assets/css/style.css">
<a href="<?= BASE_URL ?>/auth/login.php">Login</a>
```

Never hardcode `/tastybites/...` paths.
