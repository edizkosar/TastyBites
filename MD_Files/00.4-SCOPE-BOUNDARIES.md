# 00.4 — Scope Boundaries (What We DON'T Build)

> **Status:** Rules file. The hard "no" list.
> **Purpose:** When the AI feels tempted to add a feature, this is the file that says "save it for future work."

---

## ❌ Out Of Scope (Permanently)

These features are NOT part of the project. The AI must NEVER implement them, even if the user mentions them casually.

| Feature | Why excluded |
|---------|--------------|
| Online payments (Stripe, PayPal, etc.) | Requires real merchant accounts; out of academic scope |
| Email sending (SMTP, SendGrid) | Confirmations shown on-screen via flash messages instead |
| SMS notifications (Twilio) | Same reason as email |
| Real-time chat / WebSocket | Not part of the project description |
| Multi-language support (i18n) | English only |
| Mobile app (iOS/Android) | Web only |
| Google Maps embed | Plain text address is enough |
| Food ordering / delivery system | This is a **reservation** site, not a delivery service |
| Reviews / star ratings | Mention in "Future Work" slide of PPT |
| User profile editing | Out of scope. Users can register but not update their profile |
| Admin user management (promote/demote) | Out of scope. Admins are seeded directly in `schema.sql` |
| Password reset / "forgot password" | Out of scope |
| Image upload (for menu items) | Admin pastes a URL/path; no file upload handler |
| Image gallery for the restaurant | Static `<img>` tags in `about.php` are enough |
| Online newsletter / mailing list | Out of scope |
| Social login (Google, Facebook) | Out of scope |
| API endpoints (REST/JSON) | Out of scope. Server-rendered HTML only |
| AJAX features | Out of scope. Standard form submissions only |
| CAPTCHA / reCAPTCHA | Out of scope (could be mentioned in PPT) |
| File-based PHP sessions tuning | Default behavior is fine |

## ⚠️ When You Feel Tempted

If during implementation the AI thinks:

- "I should add email notification here..."
- "Let me also build a profile edit page..."
- "Maybe I'll add AJAX to make this smoother..."

**STOP.** Write a comment like:

```php
// Future work: send confirmation email to user.
// Out of scope per docs/components/00-rules/00.4-SCOPE-BOUNDARIES.md.
```

Then move on. Do NOT implement.

## ✅ What IS In Scope (The Full List)

To make the boundary clear from both sides — here's everything the project DOES include:

### Public (no login required)
- Home page with hero + 3 featured menu items
- Menu page grouped by category
- About page (static)
- Contact form (saves to DB)

### Authentication
- Register
- Login
- Logout
- Session-based auth with role distinction (`user` / `admin`)

### Logged-in user
- Make a reservation (date / time / table / party size / special request)
- View own reservations on a dashboard
- Cancel own future pending/confirmed reservations

### Admin
- Dashboard with stat cards
- Manage menu items (CRUD)
- Manage tables (CRUD)
- Manage reservations (list + filter + change status)
- View contact messages (read / mark read / mark unread / delete)

### Cross-cutting
- Bootstrap 5 styling
- Flash messages with auto-fade
- Prepared statements everywhere
- HTML escaping everywhere
- Role-based access control

That's the project. **Anything not on this list is out of scope.**
